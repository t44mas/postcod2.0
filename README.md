# Почта Премиум — B2B-прототип

Модуль участника №4 PostCode Challenge: React + TypeScript + Vite, FastAPI + SQLAlchemy + Alembic, PostgreSQL 17. Все тарифы и преимущества — модельные гипотезы; платежи и вход демонстрационные.

## Быстрый запуск

Нужны Python 3.12+ и запущенный Docker Desktop. Из корня проекта:

```powershell
python scripts/start.py
```

Скрипт создаёт игнорируемый `.env` со случайным локальным паролем, сохраняет уже существующий файл и запускает сборку трёх сервисов. Пароли не печатаются и не передаются аргументами команд. API применяет миграцию и заполняет справочники; команда ждёт готовности БД и API.

- Сайт: [http://127.0.0.1:8080/business](http://127.0.0.1:8080/business).
- Swagger / API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
- Проверка БД: [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health).
- PostgreSQL для локального подключения: `127.0.0.1:54329`, БД `pochta_premium`, пользователь `pochta`; пароль — в локальном `.env`.

Данные PostgreSQL сохраняются в томе `pochta-premium_postgres_data`. `docker compose stop` останавливает сервисы без удаления данных. Опубликованные порты ограничены `127.0.0.1`. При первом запуске нужны сеть и доступ к реестрам Docker/Python/npm; работа приложения не требует внешних API, CDN и платежных сервисов.

## Текущие возможности

Все девять B2B-маршрутов доступны:

| Страница | Содержание |
|---|---|
| `/business` | Два тарифа, условия, расчёт выгоды, FAQ |
| `/business/connect` | Демо-компания, тариф, тестовый счёт, сброс |
| `/business/dashboard` | Подписка, сотрудники, общий остаток и чистая выгода |
| `/business/employees` | Добавление, роли, отключение и повторное включение |
| `/business/benefits` | Назначения, личные лимиты, демо-использование и чек |
| `/business/invoices` | Статус и детали счёта, демо-оплата |
| `/business/operations` | Журнал, фильтры, собственная история демо-персоны |
| `/business/reports` | Итоги подписки, разрезы и детализация операций |
| `/business/economics` | Два тарифа, три сценария, CAC/LTV/MRR и безубыточность |

`/` открывает корпоративную страницу; `/personal` остаётся заглушкой. Старая корпоративная вёрстка удалена. Публичные тарифы и экономика — версия 1 модели проекта; серверный seed и тест паритета проверяют совпадение. Запись на сдачу партии и курьерские заборы P1 пока не реализованы; их затраты уже учитываются в сценариях экономики.

## Теперь данные на сервере

Рабочее приложение обёрнуто в `BackendProvider`. Компании, счета, сотрудники, назначения и операции читаются из API и сохраняются в PostgreSQL. Ошибка API показывается явно; незаметного отката к localStorage нет. После действий обновляется серверный снимок; вкладки уведомляются через BroadcastChannel и при возвращении фокуса.

Старое локальное демо **не удалено и не импортировано автоматически**. Неподключённые к Provider компоненты сохраняют локальный адаптер для изолированных тестов; рабочий маршрут всегда использует сервер. Публичные страницы и независимая экономика открываются без запроса компании.

Вход создаёт 12-часовую сессию `demo_admin`. Во frontend токен хранится в sessionStorage (или только в памяти при недоступном хранилище), в PostgreSQL — только его хеш. Демо-аккаунты намеренно не имеют настоящего пароля: это локальный показ синтетических данных, не промышленная аутентификация.

Сервер проверяет роли, компанию, статус сотрудника, подписку, срок, назначение и оба остатка. Клиент не может задать произвольную компанию/сотрудника в активации. Демо-переключение сотрудника выдаёт ограниченный серверный токен; он не открывает отчёты компании, счета или управление людьми.

Списание использует транзакцию и блокировки PostgreSQL: операция, общий и личный счётчики меняются совместно. Уникальный `(subscription_id, request_key)` исключает второе списание одного запроса. Повтор оплаты не продлевает период. Превышение мест тарифа проверяется при добавлении и включении сотрудника.

Подробный контракт, тела запросов и коды ошибок: [docs/API.md](docs/API.md).

## Демо-прогон

1. Открыть `/business`, выбрать Start или Plus.
2. Оставить вымышленное название компании и создать счёт.
3. Нажать «Оплатить (демо)» и перейти в кабинет.
4. Добавить сотрудника; в «Бонусы и лимиты» выбрать его, назначить отправления и личный лимит 100 ₽.
5. Переключить демо-роль на сотрудника, ввести цену услуги 350 ₽, применить бонус.
6. Для Plus спишется 70 ₽ лимита; личный остаток — 30 ₽. Следующая новая операция со скидкой 70 ₽ получит объяснимый отказ.
7. Журнал и отчёт покажут ту же операцию. Общий остаток Plus — 3 930 ₽, чистая выгода компании — −2 420 ₽.
8. Через подключение можно подтвердить сброс только своей серверной компании. Удалятся её сотрудники, назначения, операции и счёт; посторонние компании и старое localStorage не очищаются.

Серверный seed создаёт двух независимых владельцев `demo_admin` и `demo_other_admin`, тарифы, преимущества и правила версии 1. Компании не создаются заранее: основной сценарий начинается с подключения. Второй владелец предназначен для изоляционных и HTTP-проверок.

## Разработка без контейнера API

PostgreSQL остаётся в Docker. Нужны Node.js 24 и Python 3.12+. Из корня:

```powershell
python scripts/setup-env.py
docker compose up -d db
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install --cache-dir backend/.pip-cache -r backend/requirements.txt
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
```

Затем перейти в каталог `backend`, заполнить справочники и запустить API:

```powershell
cd backend
.venv/Scripts/python.exe -m app.bootstrap
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Не запускайте второй API на 8000, если контейнер `api` уже занимает порт. В отдельном терминале из корня:

```powershell
npm --prefix frontend ci --cache frontend/.npm-cache
npm --prefix frontend run dev
```

Dev-сайт обычно `http://127.0.0.1:5173`; Vite проксирует `/api` на localhost:8000. Собранный nginx-сайт проксирует тот же путь внутри Compose. Локальное имя БД и пароль не вшиты во frontend.

## Проверки

```powershell
npm --prefix frontend run build
npm --prefix frontend test
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini check
node scripts/check-live-api.mjs http://127.0.0.1:8080/api/v1
```

- 51 frontend/model/SSR-тест: тарифы, суммы, миграция старых данных, ошибки, роли, фильтры и реальные React-компоненты.
- 15 API-тестов на **настоящем PostgreSQL**, включая параллельные запросы одного/разных ключей, изоляцию компаний, общий и личный лимиты, отключение сотрудника, отзыв сессии, статусы подписки и границу периода.
- Тесты БД создают и удаляют только собственные схемы `test_<uuid>`. Приложенческие таблицы не очищаются.
- HTTP-прогон вызывает реальный frontend-адаптер через Vite или nginx; проверяет хранение между сессиями, оплату, сотрудников, права, лимиты, повтор и отказы. Если тестовый профиль уже занят компанией, данные не изменяются. Сверяются также все 6 сценариев экономики frontend/API.
- Docker-сборка и запуск всех трёх сервисов проверены; health API подтверждает соединение с PostgreSQL. `alembic check` не обнаруживает расхождения схемы с ORM.

SSR и HTTP-проверки не заменяют клики и визуальную проверку. Браузерный инструмент в текущем окружении не запускался из-за Windows sandbox; полноценный браузерный E2E и адаптивность после API-интеграции остаются непроверенными.

## Правила расчёта

Start: 990 ₽/месяц, 10 сотрудников, общий лимит 1 500 ₽, скидка 40 ₽ на отправление. Plus: 2 490 ₽/месяц, 30 сотрудников, лимит 4 000 ₽, скидки 70 ₽ на отправление и 40 ₽ на упаковку. Это гипотезы, не официальные тарифы Почты России.

В операции скидка не превышает исходную цену и требует достаточных общего и личного остатков. Суммы хранятся в целых копейках. Даты API — UTC; интерфейс и фильтры — Москва. Личные лимиты не резервируют общий остаток. Отключение/снятие права сохраняют историю.

Чистая выгода = применённые скидки − оплаченная подписка. Контроль: Plus, 40 отправлений и 10 упаковок → 3 200 − 2 490 = **710 ₽**. Отрицательный результат не скрывается. Итоги отчёта относятся ко всей подписке; фильтры меняют детализацию, не распределяя произвольно полную плату между сотрудниками.

Экономика оператора отдельно учитывает льготы по базовым отправлениям, маржу только прироста, P1-курьеров/слоты, поддержку, фиксированные расходы и привлечение. Таблица допущений и формулы доступны на странице. Положительные LTV и безубыточность не выдумываются при отрицательном вкладе. Все параметры — допущения прототипа.

## Структура

- `backend/app` — модели, схемы Pydantic, сессии, права, транзакции, сериализация и маршруты.
- `backend/migrations` — воспроизводимая начальная Alembic-миграция.
- `backend/tests` — интеграционные PostgreSQL-тесты.
- `frontend/src/app` — Provider серверного состояния; `services/businessApi.ts` — HTTP-клиент.
- `frontend/src/pages/business` — девять страниц участника №4.
- `frontend/src/features/business` — общие типы и расчёты, локальные тестовые адаптеры.
- `scripts/start.py`, `setup-env.py`, `check-live-api.mjs` — запуск, локальная конфигурация и проверка.
- `docs/ARCHITECTURE.md` — версия архитектуры из предоставленного файла `(3)`; `docs/API.md` — контракт API.

Зависимости frontend зафиксированы в `package-lock.json`, backend — в `requirements.txt`; диапазоны для обновления — в `requirements.in`. Лицензии пакетов содержатся в установленных дистрибутивах. React/Vite/TypeScript/FastAPI/SQLAlchemy — MIT, Golos Text — OFL, Lucide — ISC; дополнительные лицензии backend указаны в метаданных Python-пакетов.
